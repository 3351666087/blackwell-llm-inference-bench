# 一张 Blackwell 工作站卡上的 vLLM、SGLang 和 TensorRT-LLM

*Rui Huang — 草稿*

我想做一个面试时能逐行讲清楚的推理基准：一张卡、三个推理框架、开跑前先写下预测、每个数字都能追溯到逐请求的原始文件。
卡是按小时租的 RTX PRO 6000 Blackwell Server Edition（sm_120，96 GB GDDR7，1597 GB/s）；模型是 Qwen3-8B（BF16 和 FP8）
和 Qwen3-32B（FP8，外加 NVFP4）。代码和大部分文字由 coding agent 完成；问题、预算和规则由我定，结果由我验收。
仓库：https://github.com/3351666087/blackwell-llm-inference-bench

## 先定规则，再看结果

测之前先提交了预注册文件（git tag `prereg-v1`）：负载、并发扫描方式、每个点 3 次重复、统计方法和 13 条量化预测。之后的每次
改动都写进修订记录，注明时间和当时已经看到了哪些数据。任何一条自动检查失败，这次运行就作废——最重要的一条是"不能快过物理极限"：
每个解码步都要把全部权重读一遍，所以每个输出 token 的时间不可能少于"每步读取字节 ÷ 显存带宽"。Qwen3-8B BF16 的这个下限是 9.48 ms。

## 发现一：单并发时，三个框架一样

8B BF16 单路解码：SGLang 每 token 11.29 ms，vLLM 11.57，TensorRT-LLM 11.65，都达到带宽下限的 81–84%。多出来的约 2 ms
几乎不随权重变化（FP8 权重时差不多，64 层的 32B 模型约为两倍），所以它是每层的固定开销，而不是带宽没跑满。这也解释了为什么
FP8 把字节减半，8B 的解码步却只缩短到 0.61–0.65 倍。

## 发现二：一上负载就不一样了

32B FP8 聊天负载，SGLang 峰值 3581 token/s，vLLM 2629，TensorRT-LLM 2646。我预测 SGLang 和 vLLM 相差在 ±10% 以内，实测 +36%。
一部分原因是同样批量下 SGLang 的解码步更短（并发 256 时 74 对 91 ms）；另一部分是 KV cache 满了以后的策略：vLLM 继续接纳请求，
所有请求一起变慢；SGLang 让新请求排队，保证正在跑的请求速度。按一个现实的延迟目标（首 token ≤ 1 s、每 token ≤ 50 ms），这两个峰值点
其实都不能用——有效吞吐（goodput）的最优点在并发 128。峰值吞吐和有效吞吐选出来的工作点不同。

## 发现三：agent 负载撞上 KV 墙，三个框架都一样

agent 负载回放多轮工具调用会话，每一轮的 prompt 有 86% 和上一轮相同。前缀缓存效果很明显：首 token 时间降低 3.4–3.8 倍，吞吐提高
2.7–3.0 倍。但每个会话的历史都得留在 KV cache 里，等它的下一轮。每个会话平均约 5.3k 私有 token，64 个会话放得进 8B 模型约 50 万 token
的池子，128 个放不进——三个框架恰好都在这里掉下悬崖：命中率 0.85 → 0.45，吞吐减半，首 token 延迟到 12 秒。32B 模型的池子只有约 20 万，
悬崖提前到 64 个会话。这个上限用纸笔就能算出来。

## 哪里出了错，又是怎么被抓到的

这个项目最有价值的部分是错误清单。最严重的是预注册里的一个规程错误：它认为 TensorRT-LLM 在两次重复之间不用清缓存，因为聊天
prompt 各不相同——却忘了每次重复回放的是**同一批** prompt。结果第二次重复时 8k 预填充只用了 104 ms，而不是 497 ms。抓到它的有两条：
这个数字在这张卡上物理上不可能；服务器自己返回的 `cached_tokens` 显示整个 prompt 都命中了缓存。修正方法（重启或关闭块复用，再加一条
"不该命中缓存的负载出现命中就报警"的检查）写进了修订记录，被污染的运行保留在 `results/_superseded/` 并标注清楚。其他错误还有：客户端
bug 导致 GSM8K 准确率只有 0.032、密钥扫描器悄悄跳过了压缩文件、一个同步脚本差点覆盖正在写的日志。

## 几点体会

* 先算下限。带宽 roofline 把"11.6 ms 好不好"变成"82%，剩下的去哪了"——它也是最好的 bug 探测器。
* 单并发延迟掩盖了框架间的大部分差异；调度和显存策略只在负载下显现，而且好坏取决于 SLO。
* 做 agent 服务，先按"会话数 × 私有上下文"规划 KV cache。
* 把预测写下来。P11 预测错了，比 P1 预测对了教给我的更多。
